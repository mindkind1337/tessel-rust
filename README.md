# Tessel Rust

Native Rust rewrite of Tessel. **Active migration, not yet a feature-complete replacement.** The application UI and backend are Rust, using egui/eframe. No Electron, Vue or Node application runtime is bundled. External shells and agent CLIs remain separate programs; the Windows browser uses Microsoft's WebView2 engine.

The target is the same appearance, layout, menus, shortcuts and behavior as Tessel. The current native interface does not yet meet that target; visual parity is a release acceptance requirement, not an optional redesign.

## Features

### Projects and workspace

- Projects and their terminal sessions occupy the left sidebar; Files, Changes and Tasks occupy a resizable right panel. Open documents remain accessible through the center tab strip, including a direct return to Terminal. Both sidebars can be hidden from the Layout menu.
- Center tabs use compact vector icons, a selected top border and an unsaved-change dot. Document close buttons and middle-click use the existing save confirmation; holding Ctrl+W does not close successive documents; long titles are truncated with full paths on hover. Terminal and the native browser remain accessible from the same strip.
- Files, Changes and Tasks use the source panel's compact vector tabs, selected underline and tooltips showing their keyboard shortcuts.
- The project sidebar groups sessions in expandable cards with paths, counts, sleeping indicators and full-width selection. Its search button opens the command palette; the folder button opens a project. Keyboard navigation stays within the focused sidebar. Terminals started without a project remain accessible in their own section after opening a project.
- F1, the toolbar help button and the command palette open searchable keyboard help for implemented shortcuts. Escape clears its search first, then closes the overlay; the current workspace stays in place.
- Sidebar visibility and the selected right-panel tab survive restarts and settings export/restore. Ctrl+Shift+X/G/K toggles Files/Changes/Tasks, Ctrl+Shift+T opens a terminal, Ctrl+Shift+P toggles commands and Ctrl+, opens/closes Settings. Text-entry fields retain their keys, and modal confirmations block workspace shortcuts.
- An empty project presents a centered launcher instead of starting a shell automatically. It lists detected agent CLIs, native chats when a project is selected, Terminal, Browser and Open folder. Number keys or focused arrows/Enter select an action; held Enter and disabled overlays do not relaunch it. Recent-conversation discovery and remembered defaults remain pending.
- A compact top toolbar opens a command palette that searches implemented actions, projects, open sessions and documents. Grouped results show context and keyboard shortcuts; selection returns to the matching project/pane without starting a saved session. Opening the palette disables underlying terminal input and hides native browser surfaces. Full shell/layout parity remains in progress.
- The toolbar separates the tiled Tessel brand, centered command box and right-aligned controls. Vector buttons open terminal/agent menus, sharing, layout, settings and help, and directly toggle either sidebar. Open toolbar menus block underlying terminal/editor input and hide native browser surfaces. Dialog close controls sit at the right edge; native window decorations still differ from Electron.
- Settings occupies the workspace below the toolbar, with a fixed navigation column and independently scrolling content. The navigation rail uses vector controls, grouped sections and a bounded English/French search. Ctrl+F focuses search, arrows navigate the focused rail, Escape clears search first, and Back to app returns to the workspace. Appearance presents seven selectable theme cards with miniature workspace and ANSI previews, English/French controls and a terminal/editor font-size slider. Legacy light settings remain identified until a named theme is chosen. Agent detection, SSH hosts, passwords, account and backups remain available. Live Share opens as an overlay without replacing the active terminal, document or browser tab. Native browser surfaces and terminal input remain blocked while an overlay or confirmation is open.
- Windows uses its installed Segoe UI for interface text, retaining bundled fallback fonts for missing glyphs and systems without that font. Font files are not redistributed; terminal monospace text remains separate.
- Seven persisted appearance choices match Tessel's source palettes: Classic, Warp-inspired, Dracula, Nord, Tokyo Night, Gruvbox and Solarized Dark. Chrome, controls and terminal defaults update immediately; the five named palettes also supply their 16 ANSI colors. Classic/Warp retain default ANSI colors, and explicit RGB/extended terminal colors stay unchanged. Existing light-theme preferences remain readable until a named theme is selected. Segoe UI is used when available on Windows, with a 13-point base UI size. Full visual/layout parity remains in progress.
- The status bar and `--version` show the compiled Git build and commit, so portable copies can be identified without consulting the source checkout. Builds without Git metadata are labeled as source archives.
- The 24-pixel status bar shows the selected terminal/chat pane and the current project's pane count. Wider windows also show the project path; long text is clipped with a tooltip. Resource usage, ports and keep-awake controls are still pending.
- Persistent local projects; newly added projects become selected automatically.
- The built-in agent catalogue includes all 42 presets from the source Tessel catalogue, with their display names, executable mappings and static launch arguments. Existing `cursor-agent` session identifiers and visibility preferences remain compatible with the canonical `cursor` entry. Preset metadata includes material adapted from Orca; see [Third-Party Notices](THIRD_PARTY_NOTICES.md).
- Agent CLI detection runs in the background at startup and on explicit refresh. Refresh keeps the last completed results visible, prevents duplicate scans, and reports worker failures without replacing the previous list. Windows resolves the catalogue in one hidden `where.exe` batch, with a ten-second deadline and a bounded result size.
- Agent detection and newly launched terminals share an extended search path: existing PATH entries come first, followed by installed Kimi Code, OpenCode, Cursor, Ollama, npm, Bun, local-bin and Windows Python user-script folders. Refresh rescans those folders in the background. Kimi detection rejects obsolete Python `kimi-cli` executables when they are the first match, rather than claiming that the newer Kimi Code installation is available.
- Missing agents can expose a copy-install-command action using the source catalogue’s checked installer steps. Multi-step instructions keep their line breaks. The catalogue retains installer shell, source page, confirmation requirement and documentation-only choices; copying does not run an installer. The confirmed in-terminal installation flow is still being ported.
- Agents settings groups installed and missing agents, expands one agent’s launch details at a time, and connects visibility switches, terminal/native-chat launch, documentation links and copy-install instructions to the backend. Native chat requires a selected project. Agent rows show the launch command below the name, with a separate visibility switch and disclosure chevron on the right. Escape within the expanded row folds its details and returns keyboard focus to the row; unrelated Settings controls retain their Escape handling. Agent rows use native vector brand icons and contrasted initial tiles for other catalogue entries; hidden agents are dimmed. Permission/update controls and exact visual parity are still in progress.
- Agent menu visibility can be changed in Settings. Hidden agents disappear from the launcher, empty-project choices and native-chat commands; existing panes remain open. Visibility preferences survive restarts and portable settings backups, and failed saves retain the previous visibility. Portable exports omit agent environment values; imports discard agent command, argument and environment overrides. Agents settings now edits command, argument and environment overrides for newly started or reconnected terminal panes. Fields commit on leaving the control; Reset clears the overrides while preserving visibility. Invalid environment blocks are reported and are not passed to the process. Default model and launch-supported effort/Fast/Thinking choices can be saved per agent from the built-in or cached model list. Model and effort fields wrap side by side where space allows, with English/French labels and explicit Fast/Thinking switches. Their keyboard-accessible menus support prefix search; Escape closes the menu before folding agent details or closing Settings. New or reconnected agent terminals apply only explicit choices; manually supplied model/effort arguments take priority. Clearing the model restores the CLI’s own default and retains per-model choices for later. Refresh models asks the installed Claude, Codex, Grok, OpenCode, Pi, Cursor or Antigravity CLI for its list only when clicked. Progress, errors, localized model counts and regional dates in the local time zone are shown beside the picker; failures preserve the last successful list. The sanitized cache loads on restart without running a provider, and discovered options feed new/reconnected terminal launches. A failed cache write retains the list in memory and reports the problem. Closing waits for an active query/cache write to finish. Muse refresh reads its local model catalogue first; otherwise it starts the native server directly for an initialize/model-list exchange, without creating a session or inference turn. Output and runtime are bounded, and the process is closed after the reply. Cursor effort, Fast and Thinking variants are grouped into model rows; launches select an available concrete variant from the discovered list. Saved terminal metadata now preserves explicit per-pane model choices across restart and portable backup; waking a pane applies its complete choice before global defaults, while manual CLI arguments still win. Running terminals show a pending-settings label when their effective launch settings change; comparison uses an opaque local fingerprint that is excluded from backups. Claude and OpenClaude terminal panes now save their conversation ID. Waking a pane checks for its transcript on a worker and resumes it when present; explicit user session flags keep control. Old panes acquire an ID on their next managed launch. Pane menus can copy the known conversation ID for these terminals and native chats, showing the source menu label and abbreviated ID. Codex terminal panes discover their conversation from bounded local metadata scans by folder and launch time, excluding IDs already claimed by another pane. Once found, the ID survives restart; waking verifies the original metadata in the current CODEX_HOME profile (including archives) before issuing resume. Missing or mismatched conversations produce an error without silently starting another one. Discovery remains heuristic until the ID is found. If the app closes first, local recovery metadata preserves the original search time and an opaque profile/folder identity. Waking searches before launching a process; missing history, a changed profile or an expired thirty-day search window produces an error instead of silently creating another conversation. After a recovery error, an explicit button can start a new conversation. Recovery metadata is excluded from portable backups. On Windows, the menu and Ctrl+Shift+R can restart shells and managed Claude/OpenClaude/Codex terminals with known IDs. The old terminal process group must finish before a replacement starts; known agent conversation IDs are reused and changed settings are applied. The pending-settings label is clickable for supported panes. Stop failures are reported without launching a replacement, and repeated restart requests are ignored while one is pending. There is no automatic restart. Terminal pane menus now open a native Model picker with per-pane model and launch-supported option choices. Choices are saved transactionally before they affect a future launch; storage failures retain the previous choice. Selecting Default restores inheritance from Settings. Manual CLI flags still win. Running terminals keep their process and expose the existing pending-settings/restart action where supported. The picker does not send live slash commands yet. Verified restart on other platforms/providers, live switching, native-chat defaults and permission controls are still being ported.
- Agent panes receive stable human names from the source application’s name list. The pane menu can rename an agent; names remain unique ignoring case and survive workspace restart and backup restore. Provider/program titles remain separate. Native Codex chats can list named agent panes in their own project through `tessel_agents`; the list contains names and provider identifiers, not private session data or inferred activity.
- SSH Settings can add, edit and confirm removal of saved host/folder targets, or open an explicit SSH terminal. Failed metadata saves retain the previous saved list. Removing a target does not close a running connection. Import discovers aliases from the user’s OpenSSH config and its Include files on a background worker, with shared file/byte/glob limits, bounded environment/token expansion and key-file exclusion. Include account/hostname tokens use native system identity. Existing manual folders are preserved, failed batches leave saved targets unchanged, and partial discovery is reported. Connection testing is not yet implemented.
- Saved theme, font size, per-project terminal split layouts, SSH hosts and per-project task boards. The task board stacks its four status sections in narrow panels and uses four columns when space allows. Cards show status colors and counts; adding and moving tasks remain scoped to the active project, and changing projects clears the unfinished task draft.
- English/French interface selection in Settings, applied immediately and retained across restarts. Main navigation, settings, task columns, file actions, browser/download controls, PDF controls, sharing, vault and approval captions are translated. User content, tool protocol values and external/technical error messages retain their original text. Settings remain scrollable on smaller windows.
- Terminal and agent metadata restored asleep: reopening the app never automatically executes saved processes.
- Export/import portable Rust settings as bounded JSON, with a review of project paths and metadata counts before replacement. A local copy preserves previous settings; restored terminals stay asleep, projects require explicit selection, sharing stops and agent-browser access is revoked. Active work must be stopped or saved first. Exports contain paths and metadata but no credentials, browser profiles or project files, and are not encrypted.
- Atomic workspace writes, schema validation and a single-instance workspace lock. Corrupt or newer metadata is retained instead of silently replaced.

### Terminals, agents and SSH

- The toolbar launcher and Ctrl+Shift+Space open a compact terminal/agent menu with keyboard selection. Available CLIs and native chats are grouped separately; unavailable choices explain why they cannot launch. Choose automatic placement or split left, right or below the selected pane in the active project. Launching a native chat creates a new independent pane, including another instance of the same provider.
- Real PTYs (ConPTY on Windows) in independent panes and persistent project split grids. Split right/down from a pane's `⋯` menu or its title's context menu or Ctrl+Shift+E/O, drag or keyboard-resize dividers, maximize/restore a pane, and move focus with Alt+Arrow. The Layout menu can arrange existing panes automatically or into columns. Switching projects keeps existing sessions running and drains their output; restored sessions stay asleep.
- Pane header menus expose available native actions: copy terminal output, maximize/restore, arrange, split and close. Their menu, maximize/restore and close controls use Tessel's vector icons. Native chat panes do not offer terminal clipboard actions.
- Ctrl+Shift+W closes the selected terminal/chat pane in the current project. Holding the shortcut cannot close successive panes, and dialogs and text fields retain their input. Closing the final pane also saves the empty layout immediately.
- Native Codex and Claude chats share the project split grid with terminals. Open either provider from the launcher or command palette; a project can contain multiple independent panes of each provider. Resume identifiers and activity belong to each pane. Existing project-level resume metadata migrates once into its saved pane. Restoring layouts creates no agent process or connection; closing one pane leaves the others running. Closed-pane thread metadata is retained locally, but a history picker for those closed panes remains pending.
- PowerShell without user profiles on Windows; `/bin/sh` on Unix.
- ANSI colors, underlines, cursor, resize, scrollback, copy-visible-text menu, bounded paste, bracketed paste and application cursor keys. Wide glyphs render above both cell backgrounds; painting is clipped to each pane. Installed Windows emoji/symbol fonts are used as fallbacks.
- Ctrl+A–Z, Ctrl+Space, Shift+Tab, Insert/Delete, Page Up/Down, F1–F12 and modified navigation/function keys. The input cursor is hidden while viewing scrollback.
- Drag to select terminal text; copy with Ctrl+C when selected, Ctrl+Shift+C or the context menu. Wrapped lines and Unicode are preserved; new output, scrolling or resizing clears the selection. Ctrl+C without a selection still interrupts the shell.
- Click to focus a terminal; background panes never take focus automatically. Tab, arrows and Escape stay with the focused terminal. IME preedit is drawn locally and only committed text is sent, with the candidate position at the cursor; OS-specific IME acceptance is still pending.
- Terminal applications can request X10, VT200, button-motion or any-motion mouse input, using legacy, UTF-8 or SGR coordinates. Clicks, drag and wheel events stay inside the pane; Shift keeps local selection/scrollback, and losing window focus releases held buttons.
- Bounded input/output queues and shell termination on sleep or close.
- Detection and explicit launch of installed Claude, Codex, OpenCode, Gemini, Copilot, Aider, Amp, Kimi, Qwen, Grok, Cline and Cursor agent CLIs.
- SSH terminals through OpenSSH, config aliases, host verification, explicit reconnect, remote working directory and keepalives. No production server is contacted automatically.

### Files and Git

- Ctrl+Shift+J or the command palette opens a fuzzy project-file finder with keyboard selection. Enumeration runs off the UI thread, skips build/dependency directories and links, and reports truncated results when its limits are reached. Closing the finder or switching projects cancels its single worker cooperatively; late results cannot open a file from the old project. Selected files still pass the editor's project-scope checks.
- Background directory loading with virtualized rows; paths are confined to the selected project and symlinks are not traversed automatically.
- Local file/folder creation and context-menu rename/deletion, scoped to the selected project. Windows rename refuses existing targets atomically; permanent deletion requires confirmation and only removes files or empty folders. Unsaved edits block file mutations, open paths follow renames, and background directory results cannot overwrite a newer refresh.
- UTF-8 text editor tabs (2 MiB limit), atomic saves, detection of external edits and unsaved-change guards on close.
- The Changes panel displays branch context, conflicts, staged/unstaged/untracked groups, a file filter and tree/list views from an on-demand bounded Git status. Clicking a listed file opens it through the project-confined document loader. Nested project folders are scoped explicitly and repository-relative paths are mapped back to the selected project. Unrepresentable or truncated status is identified, and crossing-project rename paths are refused. Explicit row/group staging and unstaging use a bounded, literal, NUL-delimited file selection after complete-status and project-scope checks; the panel refreshes once after a Git operation finishes. Discard, panel commit and remote actions remain hidden until their native handlers are connected. Existing working/staged diffs, recent history, project-confined single-file literal-path staging (including tracked deletions) and explicit commits remain available under the collapsible Git commands section. No continuous Git polling; each Git subprocess has a 20-second deadline and bounded captured output, with an explicit truncation notice for oversized results. Results stay attached to the originating project and path; changing projects clears the displayed output and staging/commit drafts, and late results cannot appear under another project.

### Remote files

- On-demand SFTP browsing, original-file downloads (16 MiB) and UTF-8 editing (2 MiB) through OpenSSH config and existing key/agent authentication. Unknown host keys are refused; no background polling or automatic production connections.
- Canonical remote-root checks, bounded directory reads, a 30-second connection setup deadline and a five-minute operation deadline. Individual SFTP requests retain their 10-second timeout. Interrupted saves attempt temporary-file cleanup for up to five seconds and report unconfirmed cleanup. Saves compare the opened bytes again before atomic replacement and preserve ordinary permissions/ownership; servers without atomic rename support are read-only.
- Create empty files and folders directly in the current remote directory. Exclusive file creation and server mkdir refuse existing names; names cannot supply path separators or traversal. New files request owner-only 0600 permissions and folders 0700.
- Preview remote PDF and image originals directly in the panel, with bounded background decoding and the same isolated PDF renderer as local files. Temporary preview files are removed after loading; original bytes remain available for download.
- Explicitly confirmed deletion names the host and path. It permanently removes a file or an empty folder; there is no recursive deletion or remote recycle bin.
- Rename remote files and folders through their context menu. Existing destinations, changed targets and the remote root are refused; open document paths follow a successful rename.
- Unsaved edits and active requests block accidental close or host changes. Local downloads never overwrite an existing file. Password-only SSH authentication is not implemented yet.

### Document previews

- Native readable HTML and Markdown views, with source/preview switching and copy-as-plain-text. Scripts, CSS and external resources are never executed or fetched by this view; it is not a full webpage renderer.
- The Files panel is an expandable directory tree with on-demand background reads, cached rows and remembered expansions across refreshes and project switches. One worker handles enumeration; obsolete results are discarded. Limits bound directory entries, cached directories, depth and scan time between filesystem calls; an OS call itself cannot be interrupted. Existing file-operation confirmations and project confinement remain in force.
- Document tabs distinguish matching filenames with their parent folder. Ctrl+W in the editor, middle-click or the context menu closes a tab with the existing unsaved-change confirmation; closing a neighbor preserves the selected document. Editor save/close shortcuts are inactive behind a modal. The context menu can also copy its full path.
- Local links open another editor tab while preserving the source; HTTP(S) links open the private browser. Native URL schemes, network-share links and paths outside the source project are refused.
- Read-only PNG, JPEG, WebP, GIF-first-frame and BMP previews, with background decoding, compressed-size/dimension/allocation limits and fit-to-width display.
- Original PDF page rendering in Rust with previous/next page, zoom and fit-width controls. Rendering runs in a disposable worker with a 20-second deadline; Windows additionally enforces a 512 MiB process-memory limit. Closing the document cancels its worker.
- PDF inputs are limited to 32 MiB/2,000 pages; raster output is bounded to 4,096 pixels per side and 8 million pixels. The source file is never rewritten. Unsupported or damaged documents report an error; forms, text selection and every PDF feature are not supported yet.
- Office parsing runs in a disposable worker with the same 20-second/512 MiB Windows limits as PDFs, for local and SFTP originals. Inputs are limited to 32 MiB; sheet/slide, row, column and output limits bound previews. Macros and formulas are never executed. Damaged/encrypted/unsupported inputs report an error.
- Bounded document loading and up to 24 open or loading documents. Office previews accept DOCX/ODT readable paragraphs and headings, PPTX/ODP text in slide order, and XLSX/XLSM/ODS sheets with cached cell values. These are content previews, not layout-faithful Office renderers; document tables are flattened and embedded images/charts are not displayed.

### Native Claude chat

- Claude provider in a native project grid pane, using the installed Claude Code CLI and its existing sign-in. Tessel does not copy the CLI's tokens.
- Streamed text, explicit connection and resume, model selection, persisted session IDs, interruption and process-tree shutdown on Windows. Workspace restore never starts Claude automatically.
- Tool permission requests show their original arguments with Allow once / Deny. Interrupted, cancelled, duplicate or mismatched-session requests cannot gain approval. Project customizations, hooks and external MCP servers are disabled for this connection; the CLI's default permission mode remains active.
- Inline Claude questions support single or multiple choices and free text, with no preselected answer. Skipping denies the question request; cancelled, completed or interrupted turns clear pending questions. Answers preserve the original question text and do not grant unrelated command permissions.
- Bounded transport queues, frame sizes and transcript display. The native initialization test connects to the installed CLI without sending a model prompt; protocol fixtures cover streaming, approvals, cancellation and failures. The optional `--self-test-claude-turn` sends one synthetic message and refuses every tool request. The current live model test is blocked by the CLI reporting that sign-in is required. End-to-end model/tool execution, history rendering and native Tessel tools for Claude remain pending.

### Native Codex chat

- Rust client for the installed Codex app-server, using its existing sign-in without copying tokens.
- Streaming text, tool events, model/effort fields, follow-up steering, interruption, thread-ID persistence and explicit resume.
- Workspace-write sandbox and approval-on-request explicitly requested and checked. Unknown requests fail closed; approval requests are tied to the active thread and turn.
- Project-scoped task-list/add/move tools connected to the native task board. Model arguments cannot select another project's authority.
- Structured agent questions appear inline with explicit choice/free-text answers and a skip action. No choice is preselected or sent automatically; stale or resolved requests disappear. Secret-input requests are refused in favor of site sign-in. Questions do not grant command approvals.
- Pending approvals are displayed inside the chat instead of stealing focus with a popup. Allow is disabled when action details are missing or the requested permission scope is unsupported; stale-turn events cannot change the active conversation.
- Bounded resumed-history rendering, pagination when supported and a legacy read fallback. Some Codex app-server builds advertise these schemas but reject both history methods; the UI explicitly reports that limitation while leaving chat usable.

### Windows browser

- Embedded WebView2, back/forward/reload, address bar, separate persistent Rust-app profile and no website-to-native IPC bridge.
- The address bar accepts bare domains, local development addresses such as `localhost:5173`, and Google search terms. Navigation rejects URLs containing usernames/passwords and native schemes; agent navigation still requires an explicit URL.
- Original HTTP(S), authenticated and blob downloads remain inside the browser session. A fresh directory per download prevents duplicate names overwriting existing files.
- User-selected download folder, received/total bytes, separate completed/cancelled/failed states, native cancellation and copyable saved paths. At most eight transfers run at once; the last 100 transfers stay in memory. Transfers with no data progress for 120 seconds are stopped and reported as failed. Download URLs, cookies and tokens are not logged.
- New-window requests can be opened explicitly in the existing tab. Native/file URL schemes from websites are refused.

### Project agent browsers

- Explicitly enable an isolated, temporary browser for a project's native Codex chats from **Browser > Project agent**. Chats within a project share that explicitly enabled browser, with serialized operations and replies routed only to the originating pane. Up to four projects can have separate browsers; access is disabled again after app exit and can be revoked immediately.
- Newly started native chat threads register the browser tool; threads created before this feature may need a new conversation (stop the chat process, clear the resume ID, then connect).
- The `tessel_browser` tool provides bounded page snapshots, HTTP(S)/blob navigation, selector clicks, text-field entry, single-choice dropdown selection, checkbox/radio selection and scrolling to an element. Snapshots include bounded option lists, checkbox state and viewport scroll position. DOM action requests require the snapshot's exact origin, and ambiguous, hidden, disabled, password and file fields are refused. Arbitrary script execution is not exposed.
- The agent can save a viewport PNG with `screenshot(origin, folder, filename)`. Capture uses WebView2, checks the exact HTTP(S) origin before and after capture, returns the saved path/dimensions, and stays inside an existing project folder with a unique destination. One capture at a time, a 20-second deadline, 4,096-pixel side limits and a 32 MiB output limit apply. It never captures the desktop or the owner browser.
- Prepare the next download with an existing project-relative folder and a safe filename, then trigger the website's original download. A unique subfolder prevents overwrite; the one-use plan expires after 60 seconds. Agents can query the download ID, received/total bytes, completion/error status and saved path without a Save As popup, and cancel an active transfer by its ID.
- These profiles never copy owner-browser cookies or access the password vault, and are not exposed through LAN sharing. Sign in manually within the agent browser when needed. Page content is untrusted; enabling agent access allows the agent to read and interact with that project's browser session.
- Iframe interaction and arbitrary popup control remain unavailable in the initial tool set.

### Native LAN sharing

- Explicit read-only host and guest sessions over TLS with an invitation-pinned certificate and a random access token. Stopping sharing revokes the invitation.
- Project-confined listing and original-file downloads (8 MiB per file), with no shell, write, browser or vault APIs. Dot paths, app-data paths and known credential filenames are excluded; ordinary project files still need to be suitable for sharing.
- Connection deadlines, concurrency and frame-size limits; guest downloads never overwrite existing files.
- Direct LAN connectivity only. This protocol does not interoperate with Electron Tessel Live Share or provide its cloud relay and collaborative editing yet.

### Private Windows password vault

- Explicit CSV import from Chrome, Edge or Firefox exports, stored with Windows user-bound DPAPI encryption outside project folders.
- Atomic saves, exclusive vault lock, duplicate-account updates, account removal and manual locking. Invalid input retains existing records.
- Manual fill in the private browser only, restricted to the account's exact HTTPS origin; no automatic form submission. Ambiguous forms are left untouched.
- No vault tools are available to agents or guests. Existing browser password databases and Tessel credentials are not accessed automatically.

### Private Tessel account

- Owner-only Windows account panel with external-browser PKCE sign-in, bounded HTTP requests, explicit verification and sign-out. Sessions are encrypted with Windows DPAPI outside projects; agents, browsers and LAN guests have no account-token API.
- Explicit sign-in registers only `tessel-rust://` for this executable. Callback state, expiry and one-use delivery are checked; the Electron protocols and existing account files remain untouched. No account request runs on startup.
- Local sign-out removes the saved session before server revocation; connection failures are reported. Account requests finish before normal window shutdown.
- **Production activation is pending:** the account server must accept the separate Rust callback scheme. The prepared backend patch and native fixture tests pass; real sign-in has not been exercised. Connectors, account deletion and cloud sync are not implemented yet.

### Windows distribution

- An optimized portable Windows x64 ZIP can be built with `./scripts/package-windows.ps1` from a clean committed checkout. The script builds with two compiler jobs, runs the original-PDF and Office worker acceptance checks, writes commit/build metadata and SHA-256 checksums, and extracts the ZIP to verify the executable bytes.
- GitHub Actions runs formatting, tests and strict Clippy before packaging. This is an unsigned portable development build, not an installer or published product release. Windows, WebView2 Runtime, Git/OpenSSH and agent CLI requirements still apply.

## Run and verify

Install Rust stable and native C/C++ build tools. Windows requires MSVC build tools, the Windows SDK and WebView2 Runtime. Agents, Git and OpenSSH must be installed separately for their corresponding features.

```sh
cargo run --locked -j 2
cargo fmt --check
cargo test --locked -j 2 -- --test-threads=2
cargo clippy --locked -j 2 --all-targets -- -D warnings
cargo build --locked -j 2
```

Windows executable: `target/debug/tessel-rust.exe`. CI produces an optimized portable ZIP with its checksum; no installer or product release is published yet. `--data-dir <folder>` selects a separate workspace metadata directory for testing.

The Git build label tracks commits without forcing recompilation when optional Git reference files are absent. Two test threads keep synthetic child-process timing checks from competing with the entire suite at once.

Optional native acceptance checks:

```powershell
.\target\debug\tessel-rust.exe --self-test-browser
.\target\debug\tessel-rust.exe --self-test-agent-browser
.\target\debug\tessel-rust.exe --self-test-codex
.\target\debug\tessel-rust.exe --self-test-vault
.\target\debug\tessel-rust.exe --self-test-pdf
.\target\debug\tessel-rust.exe --self-test-office
```

The browser check creates a local HTTP fixture and temporary browser profile, downloads direct, cookie-authenticated and blob PDFs, and compares all saved bytes to the original synthetic PDF. Both browser checks also cancel a deliberately slow transfer after observing native progress and verify that an incomplete response cannot report completion and is stopped by the stall guard (three seconds in the fixture, 120 seconds normally). It uses no personal account. The agent-browser check repeats those original downloads with tool-selected names, checks returned paths/status, exercises snapshot/fill/click/select/check/scroll and a real nonblank PNG screenshot with project/origin rejection, refuses origin mismatch and password-field entry, and checks cookie isolation against a separate profile. The Codex check initializes the real installed app-server and verifies its applied permissions and probes history compatibility; it sends no prompt or model turn. The PDF check renders two synthetic original pages in the resource-limited worker and rejects invalid input. The Office check decodes synthetic DOCX and XLSX files through the actual isolated worker, checks original text/cached values and refuses damaged/cancelled input. The vault check uses a temporary profile and an in-process synthetic HTTPS site, without real credentials or network access. `cargo build --features visual-test` enables eframe's screenshot test support.

## Validation and remaining migration

Current Windows evidence: the integrated binary suite passes 234 tests (three fixture/reference tests ignored), and the standalone model-selector suite passes 15 tests, including the Changes panel and real nested-repository status fixtures. The per-pane model planning suite passes 17 tests, including 197 source reference vectors and opaque launch-identity/observer boundary checks; the runtime picker now saves per-pane launch choices, while live model changes remain pending.
